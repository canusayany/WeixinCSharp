# MP3 原生语音试发

历史实验：当前源码（2026-10-08，尚未发布）已停用 CLI 原生语音发送。MP3 请按 `send-media --file audio.mp3 --kind audio` 发送文件附件；以下实验记录不作为当前操作说明。

2026-10-04，Asia/Shanghai。使用已发布的 1.3.0 C# 客户端，向自己的扫码绑定机器人试发一次 MP3 原生语音。没有转换音频，也没有更改生产源码。

测试复用此前生成的两秒合成音，不使用用户录音。C# 预检读取 MPEG Layer III 帧、Info 帧计数及编码延迟/尾部补齐：24 kHz、单声道、8493 字节；编码帧总时长 2064 ms，去除延迟与补齐后内容为 2000 ms。此预检核对头部和时长元数据，没有对 MP3 做听感或解码验证。

固定官方 [VoiceItem 定义](https://github.com/Tencent/openclaw-weixin/blob/24de5c9eb0dd5e595d7e2d090ed8a3f82870d42c/src/api/types.ts#L116) 标明 MP3 为 encode_type=7，采样率单位 Hz，playtime 单位毫秒。发送声明 7 / 24000 / 2000，省略没有确定语义的 bits_per_sample。类型定义存在不代表正式音频发送器已经支持该原生外发路线；官方正式 audio 路由仍使用 FILE。

MP3 命令退出 0，持久记录中有且只有一条对应 Sent；配套文字也各有一条 Sent。电脑版实际显示“MP3测试：2秒”，两次发送后观察均未见本轮新语音气泡。微信同时弹出 C 盘存储空间严重不足的提示，因此无法完成播放验证，也不能由这个客户端状态判断所有账号的能力。

截至本记录保存时，手机结果尚未确认。结论是 API 接受了 MP3 请求，原生气泡及直接播放仍未验收成功；本轮没有把 MP3 当文件附件发送，也没有把 API 成功写成客户端播放成功。

[脱敏证据](evidence/native-mp3-v130.json)仅保留合成样本和 EXE 的 SHA、字段、状态计数及观察结果，不含账号、凭据、上下文、媒体密钥、聊天截图或用户媒体。原始状态、日志及测试文件保存在本地私有 artifacts。1.3.0 的原源码包和成品包保留发布时的字节，本记录是后续实验补充。
